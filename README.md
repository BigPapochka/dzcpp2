# ФизКат

Консольный учёт транспорта и имущества проката. Парк изначально пустой. Одна строка ввода содержит одну команду. После ошибки печатается `error: сообщение`, затем программа продолжает читать команды. Данные хранятся в памяти до выхода.

## Сборка и запуск

Требуется компилятор C++17. В PowerShell из папки проекта:

```powershell
.\build.ps1
.\main.exe
```

Скрипт ищет g++ в PATH или в установленном пакете WinLibs через WinGet. Альтернатива:

```text
g++ -std=c++17 -Wall -Wextra -Wpedantic main.cpp -o main.exe
```

В существующей конфигурации VS Code можно открыть main.cpp и нажать F5. Все реализации находятся в заголовках, поэтому достаточно собирать main.cpp.

Сценарий из условия:

```powershell
Get-Content .\example.txt | .\main.exe
```

Ожидаемый результат сохранён в example.expected.txt.

## Команды

| Команда | Действие |
|---|---|
| `add scooter id name energy score` | Электросамокат |
| `add bike id name score` | Обычный велосипед, вклад в энергию 0 |
| `add ebike id name energy score` | Электровелосипед |
| `add helmet id name` | Шлем |
| `add dock id name energy` | Док-станция |
| `add skateboard id name score` | Скейтборд, дополнительный вид транспорта |
| `list` | Все позиции по возрастанию строкового id |
| `energy` | Суммарная суточная энергия с одним знаком после точки |
| `novice [minimumScore]` | Доступный транспорт с оценкой не ниже порога, по умолчанию 6 |
| `count_novice [minimumScore]` | Число доступных новичкам единиц |
| `count` | Число позиций на балансе |
| `report` | Две строки: count и energy |
| `focus id` | Выбрать позицию для витрины |
| `show_focus` | Описание выбранной позиции или removed / expired |
| `remove id` | Удалить позицию |
| `model id` | Название модели и производитель транспорта |
| `repair id [reason]` | Отправить транспорт в ремонт; причина по умолчанию maintenance |
| `restore id` | Вернуть транспорт после успешного техосмотра |
| `repairs` | Транспорт в ремонте с причинами, по возрастанию id |
| `status id` | Состояние транспорта: available или in_repair |
| `quit` | Выход |

Имена и номера с пробелами можно заключать в двойные кавычки. Например:

```text
add scooter S-1 "City Model" 2.5 8
focus S-1
show_focus
remove S-1
show_focus
quit
```

Сортировка лексикографическая: H-10 идёт перед H-2. novice сохраняет порядок добавления. Порог должен находиться в диапазоне 1..10.

## Иерархия и полиморфизм

```text
InventoryItem
├── Helmet
├── Dock + EnergyConsumer
└── Transport
    ├── Bicycle
    ├── ElectricScooter + EnergyConsumer
    ├── ElectricBike + EnergyConsumer
    └── Skateboard
```

InventoryItem и EnergyConsumer абстрактные, с виртуальными деструкторами. Transport остаётся абстрактным из-за describe(). Множественное наследование используется у электросамоката, электровелосипеда и док-станции. Ромба нет, виртуальное наследование не требуется.

Печать выполняется через InventoryItem и виртуальный describe(). Энергия получается через EnergyConsumer::dailyEnergy(), отбор новичков - через Transport::beginnerScore(). dynamic_cast используется для проверки возможностей объекта, без перебора конкретных классов ради печати.

operator<< выводит описание позиции, operator< сравнивает id для list, дополнительный operator== сравнивает id при проверке дубликатов.

## Владение

- Registry<std::unique_ptr<InventoryItem>> внутри Fleet единолично владеет позициями.
- Transport хранит shared_ptr<const ModelSpec>. Кэш в main использует пару «вид техники, имя модели», поэтому две единицы одной модели разделяют спецификацию. Производитель равен Unknown, поскольку входной формат его не задаёт. Кэш хранит модели до завершения приложения, в том числе после удаления последней единицы.
- Каждая позиция владеет своей FocusCard через shared_ptr. В Fleet хранится weak_ptr<const FocusCard>. Это наблюдение за состоянием конкретной позиции при сохранении unique_ptr-владения самой техникой: напрямую создать weak_ptr из unique_ptr нельзя.
- При удалении позиции деструктор отмечает карточку alive=false и освобождает своего владельца. Если карточку временно удерживает lock(), флаг всё равно сообщает об удалении.
- Повторное добавление того же id после удаления создаёт новую позицию; прежний фокус автоматически на неё не переключается.
- Временные обычные указатели в list не владеют объектами и существуют только во время отчёта. Ручного new/delete в приложении нет.

Карточка содержит снимок describe() на момент focus. Команд редактирования позиции нет.

## Шаблоны

Registry<T> — динамическое хранилище с add, size, operator[], erase, sort и operator<<. Оно действительно используется для владельцев позиций и для временного списка невладеющих указателей в list.

RegistryPrinter<T> отвечает за вывод элемента. Его явные специализации для const InventoryItem* и unique_ptr<InventoryItem> печатают сам объект вместо адреса. Специализация для обычных указателей вызывается при каждом list.

Шаблонная функция sumDailyEnergy в Reports.hpp считает энергию по подходящему контейнеру. Она применяется к Registry в приложении и к vector в тестах. Это вариант с собственным шаблонным классом и обобщённым подсчётом; фиксированный Cap не используется.

## Ошибки и сохранность состояния

FleetError наследуется от std::runtime_error. Конкретные типы:

- ArgumentError: неверные аргументы, диапазоны, неизвестные команды, пустые id/name, дубликаты, отсутствующая позиция, переполнение суммы.
- InspectionError: имя транспорта содержит broken без учёта регистра ASCII.

Сначала полностью разбираются аргументы, затем создаётся объект. Техосмотр выполняется до помещения в хранилище. Отказ не меняет состав парка. Неудачный focus сохраняет предыдущий выбор. Сообщения печатаются только обработчиками исключений в main.

Энергия конечная и неотрицательная. Оценка - целое 1..10. Лишние аргументы и числовые хвосты вроде 8.5 для целой оценки отклоняются. UTF-8-имена сохраняются; поиск английского broken не является полным Unicode-преобразованием регистра.

## Креативная часть

Добавлены класс Skateboard и команда add skateboard. Дополнительная операция count_novice считает доступную новичкам технику через общий Transport. Также доступны report, count и model.

### Техобслуживание

У каждой единицы Transport есть собственное состояние MaintenanceState: Available или InRepair, а также причина ремонта. Эта информация хранится в самой единице, а не в общем ModelSpec: ремонт одного самоката не меняет состояние другого самоката той же модели.

```text
add scooter S-1 ModelX 2.5 8
repair S-1 "замена тормозов"
status S-1
repairs
count_novice
restore S-1
status S-1
quit
```

Результат:

```text
in_repair
S-1 ModelX | замена тормозов
0
available
```

repair и restore при успехе ничего не печатают. Повторный repair, возврат уже доступного транспорта, пустая причина и попытки ремонтировать шлем или док-станцию вызывают ArgumentError. Причину из нескольких слов нужно заключить в кавычки.

Fleet управляет переходами состояния через закрытые методы Transport; доступ предоставлен объявлением friend class Fleet. Перед возвратом ServiceCenter выполняет тот же техосмотр, что при добавлении. При отказе транспорт остаётся в ремонте с прежней причиной. При успешном возврате причина очищается.

Транспорт в ремонте исключается из novice и count_novice, но остаётся на балансе: list, count, energy и report продолжают учитывать его. energy показывает заявленную суммарную суточную энергию имущества, а не фактический расход только выданной техники. Фокус сохраняется на время ремонта; remove по-прежнему удаляет позицию и завершает жизнь её карточки. После повторного добавления того же id создаётся новая доступная единица.
